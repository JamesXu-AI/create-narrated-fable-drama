# Reference and capability contract

Seed Master owns any reference language it chooses in the Prompt and the Shot-local
mapping in the private Segment plan. Virtual production only resolves each unique
literal provider token. Its private namespace is an exact asset-catalog ID,
`roster--member-type`, or the reserved `continuity` namespace.

Every token resolves once, token numbers are contiguous per media kind, and media
counts remain within the refreshed provider profile. Prompt tokens must match the
private-plan token set and be introduced before the first Shot section; the private
plan and runtime media list map those tokens to values.

Order bindings by authored importance and normally target four or five total
references rather than filling the provider maximum. Reject more than four
performers that actually receive separate catalog identity/appearance image bindings
in one Segment; this is a composition recommendation, not permission to omit a
physically present role. Every provider-renderable role needs current catalog
identity/appearance authority even when temporal media visibly carries it. One
approved closed-roster image counts as one independently referenced performer asset
even though its members remain individually readable. Catalog-image bindings carry
two or three stable visible traits; person references remain single-subject images,
not multiview or collage sheets that can create duplicate identities.

For an ordinary colored predecessor-last-frame soft reference, treat the frame as
temporal authority only and still bind the current standalone identity/appearance
image for every provider-renderable role. For every extension's mandatory
white-model quality reset, the same is required:
the proxy deliberately lacks final identity, costume, texture, and color authority,
so bind one current high-resolution identity or appearance-state image for every
authorized independent performer, plus the Location master. Preflight rejects a
white-model extension that lacks any of those image authorities.

A Character Segment state does not override this reference rule. If a
`must_remain_visible` character is missing from the actual predecessor, block and
regenerate the first Segment where it vanished; do not add an identity image to a
later successor merely to make the character pop back in. Bind a separate image
after genuine absence only for an authored `re_enter`/transformation case, with the
Prompt identifying the same established character and the exact first-visible gate.

Resolution never implies semantic compatibility. Compare the resolved catalog
semantics with the private binding responsibility and approved Storyboard. Reject a
reference whose visible or audible facts conflict with the required identity,
appearance/injury, costume, prop, occupancy, environment, group, voice, sound, or
action state even when its namespace and URL are structurally valid.
